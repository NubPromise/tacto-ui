# Tacto UI 设计规范

本文件定义组件库的视觉与交互规则。全局主题角色与通用尺度位于 `tokens/tokens.css`；组件内部的局部几何值保留在组件文件中。修改主题时须同时验证文字、实色填充与状态色的配对。

---

## 1. 设计原则

**内容实，控件轻。** 内容区用实色卡加柔和阴影；玻璃材质只给控制层（导航、悬浮按钮、弹层）。这条规则决定整站的视觉重心，也是判断「该不该用玻璃」的唯一标准。

**颜色有语义。** 组件只引用 `--text-primary`、`--bg-card` 这类语义变量，不写裸色值。换肤只改令牌层，不动组件。

**状态双通道。** 错误、选中、禁用必须同时用颜色 + 形状或文字表达。色弱用户应当能完整读懂界面。

**动效短而克制。** 140–300ms，快出缓停。按压用缩放表达反馈，不用变色——变色会被误读为状态变化。

**能交给浏览器就不自己写。** 对话框用 `<dialog>`，开关用 `checkbox[role=switch]`，焦点管理交给原生。少写一行 JS，就少一个 bug。

## 2. 色彩

### 2.1 基础色板

| 令牌 | 值 | 用途 |
|---|---|---|
| `--blue` | `#2368f5` | 主色，主按钮、选中态、链接 |
| `--blue-deep` | `#1750c8` | 主色深，hover、深色文字 |
| `--mint` | `#2fbf9a` | 成功、在线、完成 |
| `--peach` | `#ff9c78` | 警告、待处理 |
| `--danger` | `#ff3b30` | 危险、错误、删除 |
| `--violet` | `#7758f4` | 辅助强调，分类标记 |
| `--cyan` | `#52d6ef` | 装饰性渐变端点 |

### 2.2 文字层级

文字三档由主墨色 `--ink-rgb` 的透明度派生，而不是三个独立灰值。这样在带色页面上文字会自然带一点底色，整体更统一。

| 令牌 | 不透明度 | 用途 |
|---|---|---|
| `--text-primary` | 92% | 标题、正文主体 |
| `--text-secondary` | 64% | 辅助说明、次级信息 |
| `--text-tertiary` | 62% | 时间戳、计数、占位符 |
| `--text-disabled` | 32% | 禁用文字 |

### 2.3 表面

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg-page` | `#f2f4f7` | `#0e1116` | 页面底 |
| `--bg-card` | `#ffffff` | `#1a1f27` | 卡片、输入框聚焦 |
| `--bg-card-soft` | `#f7f8fa` | `#171b22` | 次级表面、分段控件轨道 |
| `--bg-field` | `#f5f6f9` | 白色 5% | 输入框默认底 |

### 2.4 对比度要求

- 正文与背景 ≥ 4.5:1
- 大字号（≥ 18pt，即 24 CSS px；或 ≥ 14pt 粗体，即约 18.67 CSS px）≥ 3:1
- 图标与控件边界 ≥ 3:1
- 禁用态不要求对比度，但必须能被识别为不可用

`prefers-contrast: more` 时，`--muted` 与 `--faint` 会自动加深，玻璃降级为实色。

阈值依据 [WCAG 2.2 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。小字号按钮、徽标、占位文字也按 4.5:1 验证，不得把 px 误当成 pt。

### 2.5 强调文字与实色填充分开

`--accent` / `--accent-deep` 用于强调文字、焦点或图形；`--action-bg` / `--action-bg-hover` 用于承载 `--text-on-accent` 的按钮、发出消息和实色操作区。深色下文字强调色可以提亮，但承载白字的填充色需要保持足够深。默认两种主题的主按钮白字对比度约 4.81:1。

同理，`--success` / `--error` 是状态文字角色，`--error-fill` 是承载白字的错误填充。基础色板 `--mint` / `--danger` 不直接承担小字号文字的对比度保证。

## 3. 排版

### 3.1 字号阶梯

| 令牌 | 值 | 字重 | 用途 |
|---|---|---|---|
| `--fs-large-title` | 28px | 700 | 页面大标题 |
| `--fs-title-page` | 22px | 700 | 页面标题 |
| `--fs-title-section` | 18px | 700 | 分区标题、对话框标题 |
| `--fs-card-title` | 16px | 600 | 卡片标题、顶部栏 |
| `--fs-body` | 15px | 450 | 正文 |
| `--fs-body-small` | 13px | 450 | 辅助信息 |
| `--fs-meta` | 12px | 450 | 标签、时间戳 |
| `--fs-nav` | 12px | 500 | 底部导航标签 |

### 3.2 字重

取中间档而非整数档：`650 / 550 / 450`。可变字体（如 MiSans VF）能呈现真实字重；静态字体设备按 CSS 规则就近映射到 `700 / 600 / 400`，任何平台都不会比传统取值更重。

### 3.3 行高与字距

- 正文行高 `1.65`，长文本阅读优先
- 标题行高 `1.25–1.45`，随字号递减
- 大标题负字距：28px 用 `-.02em`，22px 用 `-.015em`
- 数字统一 `font-variant-numeric: tabular-nums`，避免跳动

### 3.4 字体栈

```css
--font-ui:   "MiSans", "PingFang SC", "HarmonyOS Sans SC", -apple-system, …;
--font-body: -apple-system, "Segoe UI", "PingFang SC", "HarmonyOS Sans SC", "MiSans", …;
```

标题与控件优先 MiSans（中文黑体，数字与标点更利落），正文优先系统字体（阅读更自然）。**不随包分发字体文件**，因此没有加载成本和首屏闪烁；未安装 MiSans 的设备走回退链。

## 4. 间距

4dp 基础栅格。组件只用语义令牌，不直接写像素。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--sp-1` … `--sp-8` | 4 / 8 / 12 / 16 / 20 / 24 / 32 | 通用间距 |
| `--page-h` | 20px | 页面左右边距 |
| `--page-top` | 16px | 页面顶部间距（另加安全区） |
| `--card-pad` | 16px | 普通卡片内边距 |
| `--card-pad-sm` / `--card-pad-lg` | 12 / 20px | 紧凑 / 大型卡片 |
| `--sec-gap` | 32px | 分区垂直间距 |
| `--touch` | 48px | 最小可点击高度 |

**节奏规则：** 同一容器内间距不超过三档；相邻元素用 `--sp-2`~`--sp-3`，分组之间用 `--sp-5`~`--sp-6`，大分区之间用 `--sec-gap`。

## 5. 圆角

| 令牌 | 值 | 用途 |
|---|---|---|
| `--r-sm` | 12px | 小图、标签、行内标记 |
| `--r-md` | 16px | 按钮、输入框、分段控件 |
| `--r-lg` | 20px | 内容卡片 |
| `--r-xl` | 24px | 大型卡片 |
| `--r-2xl` | 28px | 对话框、底部面板顶角 |
| `--r-pill` | 999px | 胶囊按钮、徽标、底部导航 |

**嵌套规则：** 内层圆角 = 外层圆角 − 内边距。例：卡片 20px 内边距 16px，内部小卡用 12px 更协调。

## 6. 层级：玻璃三层 + 阴影

### 6.1 玻璃只用于控制层

| 层级 | 令牌 | 用途 |
|---|---|---|
| tier-1 导航级 | `--glass-bg` / `--glass-shadow` | 底部导航、顶部栏 |
| tier-2 悬浮级 | `--glass-float-bg` / `--glass-float-shadow` | 悬浮按钮、圆形控件 |
| tier-3 表面级 | `--glass-surface-bg` / `--glass-surface-shadow` | 底部面板、横幅（更实，保证可读性） |

模糊参数 `blur(28px) saturate(1.65)`。饱和度的作用是让背后的彩色内容透出时不会发灰。

### 6.2 内容阴影

| 令牌 | 用途 |
|---|---|
| `--shadow-card` | 默认卡片 |
| `--shadow-card-hover` | 卡片 hover |
| `--shadow-soft` | 分段控件选中滑块 |

阴影一律双层：大扩散低透明度 + 小偏移高透明度，模拟真实光照，避免「贴纸感」。

### 6.3 层级（z-index）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--z-dock` | 40 | 底部导航 |
| `--z-overlay` | 60 | 对话框、底部面板 |
| `--z-toast` | 80 | 轻提示、顶部进度条 |

不要用魔法数字，也不要在组件里写 `z-index: 9999`。

## 7. 动效

| 令牌 | 值 | 用途 |
|---|---|---|
| `--dur-fast` | 140ms | 颜色、边框、按压反馈 |
| `--dur-normal` | 220ms | 展开、切换、开关 |
| `--dur-slow` | 300ms | 弹层入场、面板滑入 |
| `--ease` | `cubic-bezier(.22,.9,.28,1)` | 主曲线：快出缓停 |
| `--ease-out` | `cubic-bezier(.16,1,.3,1)` | 入场 |
| `--ease-spring` | `cubic-bezier(.34,1.45,.64,1)` | 小幅弹性：轻提示、点赞 |

**按压：** `transform: scale(.96)`，深色大按钮用 `.9`。不要用背景变深表达按压——那会被误读为选中。

**入场：** 位移 + 透明度，位移不超过 12px。底部面板从下方滑入，对话框轻微上浮。

**减少动画：** `prefers-reduced-motion: reduce` 时全部动画降到 `.001ms`，功能不受影响。

## 8. 布局

- **安全区：** 顶部 `env(safe-area-inset-top)`，底部 `env(safe-area-inset-bottom)`。全面屏机型必须处理。
- **底部导航留白：** 页面内容底部要留 `calc(var(--dock-h) + var(--sp-8))`，否则最后一条会被导航遮住。
- **页面边距：** 统一 `--page-h`（20px），不因页面不同而变。
- **最大宽度：** 桌面端内容区建议 `max-width: 1080px` 居中，移动端不限制。

---

## 9. 状态规范

每个数据驱动的界面必须实现四种状态，缺一不可。

| 状态 | 表现 | 规则 |
|---|---|---|
| **加载** | 骨架屏（首次）/ 顶部细进度条（刷新） | 骨架形状必须和真实内容一致 |
| **空** | 图标 + 一句话 + 可选操作 | 写「能做什么」，不写「暂无数据」 |
| **错误** | 提示条 + 重试按钮 | 说明原因和下一步，不只写「出错了」 |
| **成功** | 轻提示 | 2.4 秒自动消失，不打断操作 |

**刷新不要用整页骨架。** 骨架只用于首次加载；刷新时用顶部 2px 进度条，保留已有内容，避免页面跳动。

---

## 10. 无障碍

- **触控目标** ≥ 48×48px（`--touch`）
- **输入框字号** ≥ 16px，否则 iOS 聚焦时会自动放大页面
- **焦点环** 只在 `:focus-visible` 时出现，`outline: 3px solid var(--accent)`，偏移 3px
- **图标按钮** 必须有 `aria-label`
- **状态播报** 轻提示用 `role="status"`，错误用 `role="alert"`
- **表单错误** 用 `aria-invalid="true"` + `role="alert"` 的文字说明
- **纯装饰元素** 加 `aria-hidden="true"`
- **跳转链接** 页面顶部提供 `.ui-skip`，键盘用户可直达主内容

## 11. 扩展主题

换肤只需覆盖令牌层，不动组件：

```css
/* 品牌换成紫色系 */
:root {
  --blue: #7c4dff;
  --blue-deep: #5e35b1;
  --accent: var(--blue);
  --accent-deep: var(--blue-deep);
  --accent-soft: rgba(124, 77, 255, .09);
  --action-bg: #6d28d9;
  --action-bg-hover: #5b21b6;
}

html[data-theme='dark'] {
  --accent: #c4b5fd;
  --accent-deep: #ddd6fe;
  --accent-soft: rgba(196, 181, 253, .14);
  --action-bg: #6d28d9;
  --action-bg-hover: #5b21b6;
}
```

深色模式是独立定义的一套角色，不是简单反相。若新增主题，请同时提供 `html[data-theme='dark']` 下的对应值。

新增令牌时遵守命名：原始值用 `--{属性}-{序号}`（如 `--sp-4`），语义用 `--{用途}`（如 `--text-secondary`）。组件只引用语义层。

## 12. 深色模式

### 12.1 立场：独立的一套角色，不是反相

深色模式**不是**把浅色值取反。反相出来的界面会同时犯三个错：纯黑刺眼、彩色变脏、阴影失效。

正确做法是为深色单独定义一套语义角色，只保留同一套命名。组件代码一行不改，换的只是令牌。

### 12.2 表面：用亮度表达高度

| 层级 | 浅色 | 深色 |
|---|---|---|
| 页面底 `--bg` | `#f2f4f7` | `#0e1116` |
| 次级表面 `--surface` | `#f7f8fa` | `#171b22` |
| 卡片 `--surface-strong` | `#ffffff` | `#1a1f27` |
| 输入框底 `--bg-field` | `#f5f6f9` | 白色 5% |

**规律：** 浅色下越"高"的表面越白，深色下越"高"的表面越亮（`#0e1116` → `#171b22` → `#1a1f27`）。方向相反，逻辑一致。

深色下不要用纯黑 `#000` 作页面底。纯黑与卡片之间没有过渡空间，层级只能靠阴影，而阴影在纯黑上几乎不可见。

### 12.3 文字：不用纯白

| 层级 | 浅色不透明度 | 深色不透明度 |
|---|---|---|
| `--text-primary` | 92% | **94%** |
| `--text-secondary` | 64% | **62%** |
| `--text-tertiary` | 62% | **56%** |
| `--text-disabled` | 32% | 32% |

主文字用 94% 而不是 100%：纯白在深色底上会产生眩光，长文阅读时眼睛更容易累。

三档文字都由 `--ink-rgb` 派生，所以深色下只需要覆盖 `--ink-rgb` 一个值，四档自动跟随。

### 12.4 强调色：深色下要提亮，不是压暗

这是最容易做错的一环。

| 令牌 | 浅色 | 深色 | 原因 |
|---|---|---|---|
| `--blue` | `#2368f5` | `#5a8dff` | 饱和蓝在深底上发沉，提亮约 20% |
| `--blue-deep` | `#1750c8` | `#85b0ff` | 深色下的"深"反而更亮 |
| `--accent-soft` | 9% | **16%** | 低透明度在深底上几乎不可见，要提高 |
| `--peach-deep` | `#b8532c` | `#ffb08f` | 浅色下的深色文字在深底上不可读 |
| `--violet` | `#7758f4` | `#a48bff` | 同上 |

**规律：** 用于深色背景上文字的角色通常需要提亮；用于承载白字的实色填充要保持足够深，两者分别验证。`--*-soft` 这类低透明度底通常需要提高不透明度。

深色覆盖校验只检查令牌是否定义，不保证明暗方向或对比度数值。实际文字配对由 `test/components.html` 使用浏览器计算后的颜色验证。

### 12.5 玻璃与阴影：深色下阴影基本失效

| 令牌 | 浅色 | 深色 |
|---|---|---|
| `--glass-bg` | 白色 74%→58% 渐变 | 深灰 78%→62% 渐变 |
| `--glass-border` | 白色 65% | 冷蓝白 14% |
| `--glass-shadow` | 深蓝阴影 + 内高光 | **纯黑阴影 + 内高光** |

深色底上，深色阴影看不见。层级感改由两件事承担：

1. **边框**：冷色调的细边（`rgba(160,180,220,.14)`），比阴影有效
2. **内高光**：`inset 0 1px 0 rgba(255,255,255,.07)`，模拟光源在顶部

内容卡在深色下不靠阴影，靠表面亮度差（`#171b22` vs `#1a1f27`）。

### 12.6 图片与媒体

- **不做滤镜反相**。照片、插画、头像一律原样显示。
- 图片上的半透明遮罩用**黑色**，不用白色。浅色下用白色压暗是错的，深色下用白色会更错。
- 全屏图片查看器在两种模式下都是黑底——这是有意的，沉浸式浏览需要最暗的环境。

### 12.7 无障碍

| 机制 | 深色下的处理 |
|---|---|
| `prefers-contrast: more` | `--muted` 提到 78%，`--faint` 提到 62%，`--line` 加深到 24% |
| `prefers-reduced-transparency: reduce` | 玻璃令牌降级为实色，导航、卡片与面板统一跟随 |
| `prefers-reduced-motion` | 与浅色一致，全部动画降到 0.001ms |
| `backdrop-filter` 不支持 | 玻璃降级为 `rgba(26,31,39,.97)` |

对比度要求与浅色相同：正文 ≥ 4.5:1，大字号 ≥ 3:1。

### 12.8 实现与自动校验

主题由 `<html data-theme="dark">` 驱动，`auto` 模式由脚本同步系统偏好。

**首帧不能闪白：** 在 `<head>` 里用内联脚本在样式表加载前设置 `data-theme`，否则深色用户会看到一瞬白屏。

```html
<script>
  (function () {
    var m = localStorage.getItem('ui-theme');
    var dark = m === 'dark' || (m !== 'light' && matchMedia('(prefers-color-scheme: dark)').matches);
    document.documentElement.dataset.theme = dark ? 'dark' : 'light';
  })();
</script>
```

**自动校验：** `npm run check` 会扫描 `tokens.css`，凡是字面色值的令牌（如 `#5a8dff`、`rgba(...)`）必须在 `html[data-theme='dark']` 里有对应值，否则报错。

派生值（含 `var()` 的，如 `rgb(var(--ink-rgb) / .32)`）不在此列——它们会跟随被指向的令牌自动切换。

有意在两个主题下保持不变的常量，列在 `scripts/check.mjs` 的 `ALLOW_SHARED` 里。

### 12.9 自查清单

新增颜色或组件时逐条过：

- [ ] 新增的字面色值令牌，深色块里有对应值
- [ ] 深色下没有用纯黑 `#000` 作页面底、没有用纯白 `#fff` 作正文
- [ ] 浅色里"为了压白而调深"的颜色，深色里已调亮
- [ ] `--*-soft` 类低透明度底在深色下提高了不透明度
- [ ] 阴影换成了黑色系，或改用边框 + 内高光表达层级
- [ ] 图片没有反相，遮罩用的是黑色
- [ ] 高对比度与减少动画两种偏好都试过
- [ ] 在真机或模拟器上看过一遍，不只是调 `data-theme` 属性

## 13. 子级页面

适用于从一级页或其他页面进入的设置、编辑、详情等子页。统一采用「顶栏返回键 + 标题，正文直接展示内容」的结构。

### 13.1 标题只出现在顶栏

- 顶栏使用 `.ui-sub-header`，且只有两个实际元素：左侧返回链接 / 按钮，以及 `.ui-sub-header__title`。
- 标题使用页面唯一的 `<h1>`，在页面中线居中。右侧不放保存、更多、搜索、头像、主题切换等控件，也不添加占位按钮。
- 内容区不再出现标题：不放大标题、副标题块、分区标题或卡片标题，不使用 `h1`–`h6`、`role="heading"`、`.ui-page-title`、`.ui-section-title` 或 `.ui-list-label`。
- 表单字段的可见标签、列表项名称、普通说明和状态反馈仍需保留；它们用于说明具体内容，不作为标题块排版。分组通过间距或列表容器表达。
- `.ui-page-title` 是一级页面模式，不与子级页顶栏叠加。通用 `.ui-topbar` 的右侧操作模式不用于这里。

### 13.2 返回、操作与无障碍

- 返回控件必须有可访问名称，如「返回设置」，点击范围至少 48×48px。优先使用指向已知父级的 `<a href>`；使用路由返回时，应为直接打开、刷新或外链进入提供明确的父级回退地址，不能只依赖 `history.back()`。
- 保存、提交等业务操作放在内容区相应位置，并提供就地成功 / 失败反馈。子页使用正文标签组织信息，不能通过隐藏重复标题来伪装符合规范。
- `<main>` 通过 `aria-labelledby` 关联顶栏标题；提供跳转到正文的键盘链接。返回图标用 SVG 并标记 `aria-hidden="true"`，完整标题保留在 DOM 中，长标题视觉省略。

### 13.3 布局与安全区

- `.ui-sub-header` 保持吸顶，内容高度至少 56px，顶部安全区只加在顶栏上。左右等宽的网格轨道使标题居中，末列保持空白，不增加第三个 DOM 子元素。
- 页面外层使用 `.ui-subpage`，正文使用 `.ui-subpage__content`，不再套 `.ui-page`，避免重复顶部安全区和为底部导航预留的空白。
- 正文上方使用正常内容间距，底部保留安全区；宽屏正文居中收敛到 40rem，窄屏保留页面左右边距。顶栏始终覆盖页面宽度，长标题、字段名和说明不能撑出横向滚动。
- 使用既有深浅色令牌及玻璃降级规则，不在模板里写固定主题颜色。
